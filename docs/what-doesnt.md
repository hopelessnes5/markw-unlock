# Что не работает / ограничения (проверено или подтверждено отрицательно)

## Не использовалось осознанно

- **Официальный Mi Unlock** — отказ.
- **Разборка / тестпоинт** — отказ.
- **Патч `devinfo` без бэкапов** — отказ (риск потери данных/идентификаторов разделов).

## Не сработало или неприменимо

| Попытка/идея | Наблюдение |
|---|---|
| Dirty COW для получения root | Не сработал — ядро пропатчено |
| `fastboot oem edl` | `device locked, oem edl is not allowed` |
| DIAG 900E → EDL 9008 программно | DIAG в режиме crash dump, `qc_diag.py` не отвечает; QPST/QXDM boot не пишут; софт-перехода в 9008 не получено |
| TWRP 3.0.2-2 для установки современных zip | Ошибка `E1001` — нет поддержки brotli |
| `twrp install Magisk-v26.1.apk` | `Digest verification failed` (отсутствует файл контрольной суммы) |
| `twrp set tw_zipverify 0` | Не отключает digest-проверку в данном сценарии |
| `twrp format data` | Команда отсутствует в использованной среде |
| `twrp wipe data` для снятия шифрования | Шифрование не снимается — нужен `mke2fs` по userdata |
| TWRP, прошитый в раздел `boot` | Crash → уход в DIAG 900E; **TWRP нужно прошивать только в `recovery`** |
| Magisk v31.1 на Android 6 | `requires Android 7.0+` (для Android 11 в нашем пути использован v26.1) |
| `adb wait-for-device` при нахождении в TWRP | Висит, т.к. состояние устройства — `recovery` |

## Риски/запреты

- `fastboot oem lock` — **не делать**.
- Перепрошивка `aboot` после успешной настройки — только при полном понимании отката и наличии бэкапов.
- Операции без бэкапов `persist/modemst/fsg/devinfo/aboot` — высокий риск потери сети/калибровок/загрузки.

## Ограничения метода

- Временный root через CVE-2019-2215 применим к уязвимому состоянию стока (Android 6 в нашем кейсе); на пропатченных ядрах/других версиях путь может отличаться.
- DIAG/EDL-варианты зависят от аппаратного/программного состояния; «универсальной» программной разблокировки из 900E в этом опыте не найдено — см. [research/diag-edl.md](../research/diag-edl.md).
